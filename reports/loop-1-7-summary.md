## 문제점과 개선 거리

1. **빠른 실패 규칙이 사용량 한도를 설정 오류로 셈(루프 7).** 한도 문구 없이 몇 초 만에 끝나는 실패를 설정 문제로 보고 멈춤. 로그 끝의 `duration_api_ms` 0·비용 0 같은 한도 신호를 따로 보거나, 첫 실패에 한도 문구가 있었으면 같은 단계의 빠른 실패도 한도로 세는 쪽을 검토함.
2. **기준 데이터에서 떨어진 문항.** 합친 점수는 올라 판정에는 영향이 없지만 루프 5에 2건, 루프 6에 12건이 떨어짐. 루프 7은 0건. 판정에 넣을지(예: 떨어진 건수 상한)는 사용자 결정 거리.
3. **계획 형식 필드 추가(루프 5).** `analyze/schemas.py`의 `Plan`에 기본값 있는 필드 둘이 더해짐. 계약 검사는 통과했지만 평가자가 사람 확인 거리로 적음.
4. **실행 환경.** PowerShell에서 `bash`를 부르면 WSL이 잡혀 conda 환경을 못 찾음(루프 7의 `run-7-2.log`). 직접 실행할 때는 Git Bash를 써야 함. README나 `--check`에 알릴 거리.
5. **운영 세션의 사용량 한도.** 루프 7 중 운영 세션이 한도에 걸려 감시와 끝난 뒤 확인이 끊김. 실행기 자체는 계속 돌았음.
6. **상승 폭.** 루프 4(+0.008) 말고는 +0.01 이상이 이어짐. 방향을 다시 볼 신호는 아직 없음.
